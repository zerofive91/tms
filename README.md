# 네비게이토 암송 Festival

성경 암송 구절을 뽑고, **씨앗 · 새싹 · 잎 · 꽃 · 열매** 다섯 단계로 채점하는 웹앱입니다.
한국 네비게이토 선교회 암송 자료 **253구절**(5확신 5 · 8지침 8 · 60구절 60 · 180구절 180)이 들어 있습니다.

`index.html` 파일 하나로 돌아갑니다. 빌드 도구도, 서버도 필요 없습니다.

---

## 세 가지 모드

| 모드 | 로그인 | 하는 일 |
|---|---|---|
| **연습용** | 필요 없음 | 이름 없이 구절을 뽑고 스스로 확인합니다. 아무 데도 저장되지 않습니다. |
| **대회용** | 필요 없음 | 검사자가 채점하고 결과가 순위표에 모입니다. 같은 이름·같은 파트면 언제 눌러도 같은 구절이 나옵니다. |
| **개인용** | 구글 계정 | 채점 결과가 구절별로 쌓이고, 파트별로 자라는 정도를 봅니다. |

**채점 기준** — 열매는 다 맞춤, 꽃은 1어절 틀림, 잎은 2어절, 새싹은 3어절, 씨앗은 4어절 이상.

**순위** — 열매 개수가 먼저이고, 같으면 꽃 → 잎 → 새싹 순으로 가립니다. 점수는 화면에 띄우지 않습니다.

**개인용 다시 보기** — 씨앗·새싹·잎·꽃 중 볼 단계를 골라 그 구절만 모읍니다. **열매가 된 구절은 빠집니다.** 같은 구절을 다시 채점하면 항상 최신 결과가 그 구절의 현재 단계가 됩니다.

설정 전에 화면만 먼저 보시려면 주소 뒤에 **`?demo`** 를 붙이세요. 가짜 자료로 개인 성장 화면을 보여 줍니다.

## 설치 — 1. Supabase 만들기

채점 결과와 개인 기록을 보관할 곳입니다. 무료 요금제로 충분합니다.

1. [supabase.com](https://supabase.com) 에서 **Start your project** → 가입
2. **New project**
   - **Name** — 아무거나. 예: `navigators-festival`
   - **Database Password** — 자동 생성된 것을 쓰고 어딘가 적어 둡니다 (평소엔 안 씁니다)
   - **Region** — `Northeast Asia (Seoul)`
3. 준비되기까지 1~2분 기다립니다

## 설치 — 2. 테이블 만들기

1. 왼쪽 메뉴 **SQL Editor** → **New query**
2. 이 저장소의 [`schema.sql`](schema.sql) 내용을 전부 붙여 넣습니다
3. **Run** — `Success` 가 나오면 됩니다

> 두 번 실행해도 안전합니다. 기존 자료가 지워지지 않습니다.

## 설치 — 3. 페이지에 주소 넣기

**Project Settings → API** 에서 두 가지를 복사합니다.

- **Project URL** — `https://xxxx.supabase.co`
- **anon public** 키 — `eyJ...` 로 시작하는 긴 문자열

`index.html` 맨 위 이 두 줄을 채웁니다.

```js
const SUPABASE_URL = "https://xxxx.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOi…";
```

> **anon 키는 공개해도 되는 키입니다.** 브라우저에 노출되는 것을 전제로 만들어졌고, 실제 권한은 2단계에서 넣은 접근 규칙이 막아 줍니다. 저장소가 공개여도 괜찮습니다. Database Password 와 `service_role` 키는 여기에 들어가지 않습니다.

## 설치 — 4. GitHub Pages 로 올리기

1. 이 파일들을 담은 저장소를 만듭니다. **무료 요금제는 저장소가 공개(Public)여야 Pages 를 쓸 수 있습니다.**
2. 저장소 **Settings → Pages**
   - **Source** — `Deploy from a branch`
   - **Branch** — `main` / `/ (root)`
   - **Save**
3. 1~2분 뒤 주소가 나옵니다.
   - 저장소 이름이 `아이디.github.io` 면 → `https://아이디.github.io/`
   - 그 밖의 이름이면 → `https://아이디.github.io/저장소이름/`

주소가 짧을수록 QR이 단순해지니, 이 앱만 쓰실 거면 저장소 이름을 `아이디.github.io` 로 만드시는 편이 낫습니다.

## 설치 — 5. 구글 로그인 켜기 (개인용에만 필요)

연습용·대회용은 이 단계 없이도 그대로 돌아갑니다.

1. Supabase **Authentication → Sign In / Providers** → **Google** 켜기
2. 여기 필요한 **Client ID / Client Secret** 은 구글에서 발급합니다
   - [Google Cloud Console](https://console.cloud.google.com/apis/credentials) → 프로젝트 생성
   - **사용자 인증 정보 만들기 → OAuth 클라이언트 ID → 웹 애플리케이션**
   - **승인된 리디렉션 URI** 에 Supabase 화면에 적힌 **Callback URL** 을 그대로 붙여 넣습니다. `https://xxxx.supabase.co/auth/v1/callback` 형태입니다
   - 발급된 ID와 보안 비밀번호를 Supabase 에 붙여 넣고 저장
3. Supabase **Authentication → URL Configuration**
   - **Site URL** — 평소 쓰실 주소 하나
   - **Redirect URLs** — 쓰실 주소를 **끝에 `/**` 를 붙여** 모두 추가

   ```
   https://아이디.github.io/저장소이름/**
   ```

   > `/**` 를 빼먹으면 구글까지 갔다가 사이트로 돌아오지 못합니다. 가장 흔한 실수입니다.

   Netlify 등 다른 주소도 함께 쓰신다면 그 주소도 같은 방식으로 추가하세요. 데이터베이스는 하나라 어느 주소로 들어와도 순위와 기록이 이어집니다.

   Google Cloud 쪽 콜백 주소는 **그대로 두세요.** Supabase 주소를 가리키는 것이라 사이트를 어디에 올리든 바뀌지 않습니다.

## 잘 되는지 확인

1. 사이트를 열고 **개인용 → 구글 계정으로 시작하기** 로 로그인
2. 돌아오면 이름과 파트별 막대가 보입니다 (기록이 없으니 비어 있습니다)
3. **새로 뽑기** 로 몇 구절 채점 → **채점 완료** → **내 성장 보기** 에 색이 채워지면 성공
4. 대회용은 주소 뒤에 **`?admin`** 을 붙여 열면 관리자 칸이 나옵니다. **데이터베이스: 연결됨** 인지 확인하세요

## 관리자 화면 (`?admin`)

대회용 모드를 고른 뒤에 나옵니다.

- **대회코드** — 회차를 가르는 값. 코드를 바꾸면 모두의 구절이 새로 정해집니다
- **대회용 구절 수** — 모든 참가자가 같은 개수를 뽑습니다
- **참가자용 링크 · QR** — 대회코드와 구절 수가 담긴 주소

> **초기화 후에는 링크와 QR을 반드시 새로 나눠 주세요.** 이미 나눠 준 링크에는 옛 코드가 들어 있어서, 그 링크로 들어온 사람은 바뀌기 전 구절을 그대로 받습니다.

## 데이터

Supabase **Table Editor** 에서 언제든 볼 수 있습니다.

| 테이블 | 내용 |
|---|---|
| `contest_entries` | 대회 참가자당 한 줄. 다시 채점하면 줄이 늘지 않고 갱신됩니다 |
| `contest_verses` | 대회 구절당 한 줄. 어느 구절에서 막혔는지 남습니다 |
| `personal_progress` | 개인 구절당 한 줄. 본인만 읽고 쓸 수 있습니다 |

대회 채점은 로그인 없이 누구나 할 수 있습니다. 대회 현장에서 검사자가 바로 채점해야 하기 때문입니다. 대회가 끝나면 관리자 화면에서 새 코드로 바꿔 두시면 이전 회차와 섞이지 않습니다.

개인 기록은 접근 규칙상 본인만 화면으로 볼 수 있습니다. 대회에서 받은 채점은 개인 기록에 쌓이지 않습니다.
